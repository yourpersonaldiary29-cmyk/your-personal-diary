## 3. לאן מעלים - צעד אחר צעד ב-App Store Connect

1. נכנסים ל-App Store Connect ← **My Apps** ← רשומת **אפליקציית האייפון** ← בצד שמאל, הגרסה (**iOS App** ← 1.0
   Prepare for Submission). זה "דף הגרסה" - אותו דף שבו מדביקים את התיאור ומילות החיפוש (ראו `appstore/README.he.md`).
2. בראש הדף, מימין, יש תפריט שפות. בוחרים **English (U.S.)** - השפה הראשית. אותה ממלאים ראשונה.
3. בקטע **App Previews and Screenshots** בוחרים את משבצת הגודל **iPhone 6.3" Display** וגוררים לתוכה את 7 הקבצים
   מהתיקייה `appstore\screenshots\iphone-6.3\en-US\` **לפי הסדר**: `01-home.png`, `02-diary.png`, ... `07-offline.png`
   (אפשר לגרור את כולם יחד; אם הסדר השתבש, גוררים ומסדרים - הראשונים הם מה שרוב האנשים רואים בחיפוש).
4. באותו קטע בוחרים את משבצת **iPhone 6.9" Display** וגוררים אליה את 7 הקבצים מ-`iphone-6.9\en-US\`, באותו סדר.
   אם רואים רק משבצת אחת לאייפון, שאר הגדלים נמצאים מאחורי הקישור **View All Sizes in Media Manager** (שם הקישור
   עשוי להשתנות בין גרסאות של האתר; מה שמזהה בוודאות את המשבצת הוא הגודל בפיקסלים: 1206×2622 ו-1320×2868).
   למשבצות של גדלים אחרים לא מעלים כלום - אפל ממלאת אותן בעצמה מהסטים שהעלינו.
5. **Save** (למעלה מימין).
6. חוזרים על שלבים 2-5 לכל אחת מ-18 השפות האחרות: בוחרים את השפה בתפריט השפות (לפי הטבלה בסעיף 1), ומעלים את
   7 הקבצים מהתיקייה של אותה שפה לכל אחת משתי המשבצות. (שפה צריכה להיות מוספת קודם לרשומה - זה נעשה כשמדביקים
   את הטקסטים שלה; ראו `appstore/README.he.md`.)
7. **אפליקציית ה-Mac**: עוברים לרשומת אפליקציית ה-Mac ← **macOS App** ← 1.0 ← אותו קטע **App Previews and
   Screenshots** ← משבצת **Mac** ← 8 הקבצים מ-`mac\<קוד שפה>\` לפי הסדר `01` עד `08`, לכל שפה בנפרד, אנגלית ראשונה.

את `render-log.json` **לא** מעלים. בכל פעם שמסיימים שפה - Save.

## 5. לפני ההעלאה - בדיקה

בחלון פקודה (PowerShell או Git Bash), מתיקיית הפרויקט `C:\Users\AVI\Projects\my-personal-diary`:

```
node scripts/appstore/check-screenshots.mjs
```

הבדיקה עוברת על כל 418 התמונות ועל האייקון: שלכל אחת מ-19 השפות יש תיקייה בכל אחד משלושת הסטים ואין תיקיות או
קבצים זרים; שבכל תיקייה בדיוק הקבצים הנכונים; שכל תמונה היא PNG שלם, 24 ביט בלי שקיפות, בדיוק בגודל של הסט שלה
(ושהגודל הזה באמת ברשימה של אפל); שאף תמונה לא זהה לאותה תמונה בשפה אחרת (זה היה אומר שהשפה לא הוחלה); ושלפי
`render-log.json` כל קובץ הוא בדיוק מה שהסקריפט יצר, בדיקת הפריסה עברה, והדפדפן פנה רק למחשב הזה. השורה האחרונה
הרצויה:

`check-screenshots (App Store): 3 sets, 418 images - every set complete ...`

אם מודפסות שורות `FAIL` - כל שורה אומרת איזה קובץ ומה לא בסדר (באנגלית); בדרך כלל הפתרון הוא להריץ מחדש את
הסט שבו הבעיה (סעיף 6).

## 6. איך מייצרים את הצילומים מחדש

צריך לעשות את זה כשהמראה של האפליקציה משתנה (או התרגומים, או יומן הדוגמה), ואם רוצים שמספר הגרסה שמופיע בתחתית
המסך ב-Mac יהיה העדכני (ראו סעיף 7). שלוש פקודות, מתיקיית הפרויקט, אחת אחרי השנייה (כל אחת 8-13 דקות), ואז הבדיקה:

```
node scripts/play/render-screenshots.mjs --profile iphone-medium
node scripts/play/render-screenshots.mjs --profile iphone-large
node scripts/play/render-screenshots.mjs --profile mac
node scripts/appstore/check-screenshots.mjs
```

מה כל פקודה עושה: בונה את ממשק האפליקציה לתיקייה זמנית (לאייפון - אותה בנייה שאפליקציית האייפון מכילה; ל-Mac -
אותו ממשק שאפליקציית ה-Mac מציגה), מפעילה על המחשב הזה שרת בדיקה זמני (אותו קוד של השרת האמיתי, עם תיקיית נתונים
זמנית, רק על הכתובת הפנימית 127.0.0.1), יוצרת לכל שפה חשבון בדוי וממלאת אותו ביומן הדוגמה של אותה שפה, מצלמת
ב-Microsoft Edge נסתר את המסכים בגודל המכשיר המתאים, ובסוף עוצרת את השרת ומוחקת את כל הקבצים הזמניים. לפני כל
צילום הסקריפט בודק שאין טקסט חתוך, מוסתר או שבור; אם אין מצב נקי - הצילום נכשל ולא נשמר, והפקודה אומרת איזה.

רק חלק: `--locale he,ar-SA` (שמות תיקיות) מייצר רק את השפות האלה; `--only 01,07` רק את הצילומים האלה;
`--keep-going` ממשיך אחרי צילום שנכשל ומציג בסוף את כל הכשלונות (ואז **לא נכתב** `render-log.json` - אחרי שמתקנים
את הסיבה מריצים את הסט שוב, או רק את השפות שנכשלו עם `--locale`).

מה צריך שיהיה מותקן (כבר מותקן במחשב הזה): Microsoft Edge, ו-`playwright-core` בתיקיית הכלים `mpd-store-tools`
בתוך הפרויקט - אותו כלי שצילם את צילומי Google Play ו-Microsoft Store. הפקודות לא מורידות שום דבר.

## 7. כדאי לדעת - הבדלים ידועים ומקובלים

- **הגופן.** הצילומים נעשו ב-Windows, ולכן הטקסט בגופן Segoe UI (ובגופני Windows לעברית, ערבית, סינית, יפנית,
  תאית והינדי). באייפון וב-Mac אותם מסכים מוצגים בגופן של אפל (San Francisco). צורת האותיות, אורך השורות ובכמה
  שפות גובה סרגל הניווט התחתון שונים מעט; הפריסה, הצבעים, הטקסטים והתוכן זהים. זה הבדל ידוע ומקובל לגרסה הראשונה.
  **צילום מחדש על Mac הוא אופציונלי**: אותו סקריפט צריך שם דפדפן מבוסס Chromium (Microsoft Edge ל-Mac, או
  Chromium של Playwright בתיקיית הכלים) ואת הפרויקט עם `node_modules`; על ה-Mac שלך זה לא הותקן (אין Homebrew וכמעט
  אין מקום בדיסק), ולכן לא הוגדר. הסקריפט עצמו לא צריך שינוי.
- **אין סרגל מצב (שעה, סוללה), אין את ה"אי" של האייפון ואין שורת כותרת של חלון ה-Mac** - הצילומים הם של הדף
  בלבד, כמו ב-Google Play וב-Microsoft Store. אפל לא דורשת את זה.
- **מספר הגרסה בתחתית המסך ב-Mac - צריך לצלם שוב את סט ה-Mac אחרי שהגרסה עולה ל-1.0.0.** בשלושה מצילומי ה-Mac
  (`02-diary`, `03-entry`, `08-offline`) רואים בתחתית הדף שורה קטנה עם מספר הגרסה, וכרגע כתוב שם **`v0.1.0`**.
  בסוף הספרינט מספר הגרסה של האפליקציה עולה ל-1.0.0 (הסשן הראשי עושה את זה). אחרי זה מריצים שוב רק את הפקודה של
  `mac` מסעיף 6 (כ-8 דקות) ואת הבדיקה מסעיף 5 - ואז גם בצילומים יהיה כתוב 1.0.0. באייפון אין שורה כזאת, ולכן צילומי
  האייפון לא צריכים את זה.
- **בצילום "בלי חיבור" באייפון** רואים את התג "עוד לא הועלה" ואת ההודעה - לא את הפס הצהוב (סעיף 4). ב-Mac רואים
  את הפס המלא.
- **רשומות היום וההרגלים לא בדף הבית**: דף הבית מציג רק את מספר הרשומות של היום; הרשומות עצמן ב-`02-diary` וההרגלים
  בצילום ההרגלים. כך האפליקציה בנויה.
