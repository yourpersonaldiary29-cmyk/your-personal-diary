# App Store icon - `AppIcon-1024.png`

The 1024 x 1024 App Store icon of **Your Personal Diary** for both Apple apps, made 2026-11-09 from the app's own
artwork `design/app-icon.svg` (brief `docs/apple-tasks/SHOTS.md` "ICON"; Apple's rules in
`docs/apple-tasks/APPSTORE-FACTS.md` section 7). The Hebrew note for the owner is at the end.

| File | What it is |
| --- | --- |
| `AppIcon-1024.png` | **The icon.** 1024 x 1024 pixels, 24-bit RGB PNG (colour type 2, 8 bits per channel, no alpha channel, no transparency, sRGB chunk), square corners, 69,905 bytes |
| `AppIcon-1024.svg` | The flattened artwork the PNG was rendered from (for a future developer: Icon Composer, another renderer) |
| `render-icon.mjs` | Makes both files again (`node appstore/icon/render-icon.mjs`); `--check` only checks the PNG |

## 1. Apple's rules and how the file meets them (APPSTORE-FACTS 7.1-7.4)

* "1024x1024 px", square: "In iOS, iPadOS, and macOS, icons are square, and the system applies masking to produce
  rounded corners"; "Providing layers with pre-defined masking negatively impacts specular highlight effects and
  makes edges look jagged." - **the PNG is the full square**: the artwork's own gradient background runs to the
  edges, and Apple rounds the corners itself.
* Colour space "sRGB (color)" - **the PNG declares sRGB** (an `sRGB` chunk with the matching `gAMA`), its colours are
  the SVG's sRGB values.
* "For mesh gradients and raster artwork, prefer PNG format because it's a lossless image format." - **PNG.**
* Transparency: Apple states no alpha rule for the default icon (NOT FOUND, FACTS 7.1), but it does for screenshots,
  and the masking text implies an opaque square - **nothing is transparent** (checked pixel by pixel when rendered).
* Layered Icon Composer files are optional (FACTS 7.4): "If you provide a bitmap image instead, the system attempts
  to segment your icon" - a PNG in the asset catalog remains accepted; the SVG here is the starting point if a
  layered icon is wanted later.

Why not the existing files: `src-tauri/icons/icon.png` is 512 x 512 with an alpha channel (rounded corners), and
Tauri's generated iOS icons (`src-tauri/icons/ios/`, including `AppIcon-512@2x.png` = 1024 x 1024) carry that alpha
channel too; upscaling 512 to 1024 blurs the artwork. The SVG is the source of all of them: `render-icon.mjs` squares
its background rectangle (`rx="220"` -> `rx="0"`), renders it with headless Microsoft Edge (playwright-core from
`mpd-store-tools/`, every network request blocked) at exactly 1024 x 1024 CSS px at device scale 1, verifies the
capture is fully opaque and the corners carry the gradient, and writes it as RGB.

## 2. Where it goes

### iPhone app (Xcode project `ios/App/App.xcodeproj`, generated by Capacitor on the Mac - IOS package)

App Store Connect has **no icon upload field**: "If you distribute your app through the App Store, you must provide
app icon imagery to use in the App Store. In the Project navigator, select an asset catalog and add icon images to
the appropriate image wells ... For iOS: Drag an icon image to the iOS 1,024pt image well." and "iOS, iPadOS, tvOS,
and watchOS apps can auto-generate all icon variations from a single 1024x1024 pixel image." (FACTS 7.2). The icon
shown in the App Store is taken from the uploaded build.

1. In Xcode open `ios/App/App/Assets.xcassets`, select **AppIcon**.
2. Drag `appstore/icon/AppIcon-1024.png` onto the single 1024 pt well (labelled "iOS 1,024pt" / "App Store" depending
   on the Xcode version; a Capacitor project has one universal well). Xcode generates every size from it.
3. Without Xcode's UI: replace the file that `ios/App/App/Assets.xcassets/AppIcon.appiconset/Contents.json` names
   for the 1024 x 1024 size (Capacitor's template calls it `AppIcon-512@2x.png`) with a copy of `AppIcon-1024.png`
   under that name - the file name in `Contents.json` must stay what the catalog expects.
4. Build and archive as usual; the App Store listing and the home screen use this icon.

Because `ios/` is generated on the Mac, and `bash scripts/mac/sync-to-mac.sh` never copies `ios/` from the PC to the
Mac (it keeps the Mac's own `ios/`), make this change in the Mac project - the one that is archived - and then copy
`ios/` back to the PC (ENV-FINAL: the PC tree is the source of truth; tar over ssh). A change made only in the PC's
copy does not reach the Mac build.

**Checked:** once `ios/` is on the PC, `node scripts/appstore/check-screenshots.mjs` compares the image that
`Contents.json` names for the 1024x1024 slot with `AppIcon-1024.png` (the same file, or the same pixels as RGB without
alpha) and prints `ios   ok ...` or a `FAIL` that names the file to replace - Capacitor's template placeholder in
that slot would otherwise ship with the build and is a likely App Review rejection. The same check runs in
`node --test "scripts/**/*.test.mjs"` (the project test of `check-screenshots.test.mjs`). As of 2026-11-10 there was no
`ios/` on the PC yet (the IOS package creates it on the Mac); its brief (`docs/apple-tasks/IOS-I1.md` step 5) puts this
file into the slot.

### Mac app (Tauri bundle)

The Mac bundle takes its icon from `src-tauri/icons/icon.icns`, which Tauri builds from `src-tauri/icons/` and which
already carries the sizes up to 1024 x 1024 (`ic10`, 512@2x) - the `.app` and the `.pkg` for the Mac App Store embed
it, and App Store Connect takes the Mac app's icon from the uploaded build (FACTS 7.2: for macOS the "App Store - 2x"
well = 1024 px; a Tauri bundle supplies the `.icns` instead of an asset catalog). **Nothing to upload here.** Note
for the MAC-M4 package / a future developer: that `.icns` is rendered from the 512 px artwork with its own rounded
corners and transparency (the classic macOS style); on macOS 26 and later the system masks icons itself (FACTS 7.1),
so a regenerated `.icns` from the square `AppIcon-1024.svg` would match Apple's current guidance more closely. Not
required for the first release (Developer ID / DMG distribution shows the icon as drawn).

## 3. The check line

```
node -e "const b=require('fs').readFileSync('appstore/icon/AppIcon-1024.png');console.log(b.readUInt32BE(16)+'x'+b.readUInt32BE(20),'bit depth',b[24],'colour type',b[25])"
```

Expected: `1024x1024 bit depth 8 colour type 2` (2 = RGB without alpha; 6 would mean an alpha channel). Also run
by `node scripts/appstore/check-screenshots.mjs` (the icon line of its table) and by `node appstore/icon/render-icon.mjs --check`
(which also lists the chunks: `IHDR sRGB gAMA IDAT IEND`, no `tRNS`).

## 4. Making it again

```
node appstore/icon/render-icon.mjs
```

Needs Microsoft Edge and `playwright-core` in `mpd-store-tools/` (as the screenshots do); takes a few seconds; the
result is deterministic (the same SVG gives the same bytes). If `design/app-icon.svg` changes shape (the background
rectangle is no longer `<rect x="0" y="0" width="1024" height="1024" rx="..." fill="url(#bg)"/>`), the script stops
with a message - adapt `flattenSvg` in `render-icon.mjs`.

## הערה לבעלים (עברית)

`AppIcon-1024.png` הוא האייקון של האפליקציה בגודל 1024×1024 שאפל דורשת, בלי שקיפות ועם פינות ישרות (אפל מעגלת
אותן בעצמה). **לא מעלים אותו ב-App Store Connect** - אין שם שדה כזה. הוא נכנס לתוך פרויקט ה-Xcode של אפליקציית
האייפון (ב-Mac: Assets.xcassets ← AppIcon ← גוררים את הקובץ למשבצת ה-1024), ומשם אפל לוקחת אותו מהבנייה שמעלים.
לאפליקציית ה-Mac אין מה לעשות - האייקון שלה כבר בתוך הבנייה (`icon.icns`). לבדוק שהקובץ תקין:
`node scripts/appstore/check-screenshots.mjs` (שורת `icon ok`). ליצור מחדש: `node appstore/icon/render-icon.mjs`.

**לבדוק שהאייקון באמת בתוך פרויקט האייפון (לפני ה-Archive):** אותה פקודה בודקת גם את זה, ברגע שהתיקייה `ios` נמצאת
בפרויקט במחשב הזה - שורה שמתחילה ב-`ios`:
- `ios   ok` - האייקון בפנים. אין מה לעשות.
- `ios   FAIL` - בפרויקט עדיין יש את אייקון ברירת המחדל של Capacitor (אפליקציה עם אייקון כזה עלולה להידחות). מתקנים
  **ב-Mac**, בפרויקט שממנו בונים את האפליקציה: ב-Xcode פותחים Assets.xcassets ← AppIcon וגוררים אל הריבוע של 1024
  את הקובץ `AppIcon-1024.png` (ב-Mac הוא בתיקייה `~/Developer/my-personal-diary/appstore/icon/`). או ב-Finder:
  מעתיקים אותו לתיקייה `ios/App/App/Assets.xcassets/AppIcon.appiconset/` **במקום** הקובץ ששורת ה-FAIL מציינת, ובאותו
  שם בדיוק (בדרך כלל `AppIcon-512@2x.png`). תיקון במחשב (PC) לא מגיע ל-Mac - פקודת הסנכרון לא נוגעת בתיקייה `ios`
  שב-Mac. הבדיקה במחשב קוראת את העותק של `ios` שבמחשב, ולכן היא תראה `ok` רק אחרי שהעותק הזה מתעדכן מה-Mac.
- `ios   -    ... not on this computer yet` - פרויקט האייפון עוד לא הועתק למחשב הזה; זה לא כישלון.
