PACKAGE LISTING - the App Store texts of Your Personal Diary in 20 languages (19 App Store localizations + a Bulgarian folder that cannot be entered).

INPUTS (read only): store/listing/en-US and store/listing/he-IL (8 Microsoft Store field files - the fullest description we have), play/listing/en-US + play/listing/iw-IL (short texts), docs/apple-tasks/APPSTORE-FACTS.md (limits and locale codes - if it does not exist yet, use the limits below and say so), docs/APPLE-PLAN.md section 7.4, the app's own vocabulary in shared/i18n/messages/<locale>/{shell,settings,auth,entries,offline}.ts (feature names must match the app), legal/settings.json (publisher, contact e-mail), README.md section 1 (what the product is today).

OUTPUT LAYOUT - appstore/listing/<folder>/ where <folder> is the App Store Connect localization code from appstore/locales.json (en-US, he, ar-SA, zh-Hans, ja, es-ES, pt-BR or pt-PT, fr-FR, el, pl, cs, hu, ru, tr, de-DE, ro, it, th, hi) plus bg/ with NOTE.txt:
- name.txt - at most 30 characters; "Your Personal Diary" everywhere (Latin letters, never translated or transliterated).
- subtitle.txt - at most 30 characters, in the language (Apple counts characters, including CJK and Thai; count with Array.from(text).length).
- promotional-text.txt - at most 170 characters (can change without a new build).
- description.txt - at most 4000 characters; paragraphs separated by blank lines; no Markdown, no HTML, no emoji, no bullet characters other than "-" at line start (App Store shows plain text); first paragraph = what it is in two sentences.
- keywords.txt - ONE line, comma-separated, total at most 100 characters including commas; no spaces after commas; no words already in name/subtitle (Apple indexes those anyway); no competitor or brand names; no plurals duplicating singulars; in the language (Latin terms allowed where natural).
- whats-new.txt - at most 4000 characters; for version 1.0: a short first-release note.
- support-url.txt - https://yourpersonaldiary.fly.dev/support/<app-locale>/ (en-US: https://yourpersonaldiary.fly.dev/support/).
- privacy-url.txt - https://yourpersonaldiary.fly.dev/privacy/<app-locale>/ (en-US: https://yourpersonaldiary.fly.dev/privacy/).
- marketing-url.txt - empty file (none).
- platform-notes.md (en-US and he only) - sentences that must be read differently for the Mac App Store record vs the iPhone record, if any; aim for platform-neutral text so both records can use the same files.

CONTENT RULES (Apple App Review Guideline 2.3 and the owner's rules):
- Truthful about today's product: one account on a server (Frankfurt), the first sign-in needs a connection, afterwards the app keeps working without one and uploads when the connection returns; "Remember me" keeps an encrypted copy on the device; unlock without a connection with Face ID / Touch ID / the device passcode (iPhone) or Touch ID / the Mac password (Mac); 20 languages; calendars (Gregorian, Hebrew, Hijri) with holidays; mood/energy/stress/sleep/activity fields; habits with reminders; insights worded carefully (no medical claims; the app "does not prove cause and effect"); smart search in your own language; backups (encrypted) and exports (TXT, CSV, JSON, PDF); account deletion in Settings; no ads, no analytics, no tracking; free.
- NEVER mention other mobile platforms or their stores in App Store metadata (Guideline 2.3.10): no "Android", "Google Play", "Windows", "Microsoft Store", "Play Store". Say "on all your devices" / "the same account on every device".
- No prices, no "best", no superlatives, no promises of security that the privacy policy does not make (the policy says the operator could technically reset a password and read a diary: do not write "nobody can read it"; write "encrypted on the server with a key derived from your password").
- The brand "Your Personal Diary" stays in Latin letters in every language; product terms (Face ID, Touch ID, PDF, CSV, JSON, TXT) stay as they are.
- Right script and punctuation per language (Arabic comma, CJK punctuation, Thai spacing, French no-break spaces before ; : ! ?); RTL text needs no markers in plain files.

CHECK SCRIPT (scripts/appstore/check-listing.mjs, ESM, no dependencies, plus scripts/appstore/check-listing.test.mjs for node --test): checks every folder named in appstore/locales.json (bg excluded, its NOTE.txt required): all files present, limits per field (code points), keywords format (single line, commas, no ", ", total length), the name is exactly "Your Personal Diary", forbidden terms (case-insensitive: android, google play, play store, windows, microsoft, msix, exe) anywhere, no "{{", no tabs, no trailing spaces, URLs are https on yourpersonaldiary.fly.dev with the right locale path, description has at least 600 characters and no Markdown markers (** , ##, backticks). Exit 1 with a readable list of problems; exit 0 prints a table (locale, subtitle chars, promo chars, description chars, keywords chars). Add it to the scripts test run (node --test "scripts/**/*.test.mjs" must stay green and include your test).

appstore/locales.json: { "<app-locale>": { "folder": "<App Store code or null>", "appleName": "<Apple's display name of the localization>", "note": "..." } } for all 20 app locales (shared/i18n/locales.ts has the list), with the Portuguese decision recorded in "note" (look at shared/i18n/messages/pt/*.ts spelling: Brazilian vs European).

appstore/README.md (English, for a developer) and appstore/README.he.md (Hebrew, for the owner): what each folder holds, which App Store Connect field each file goes into (name the screen and the field label as App Store Connect shows it), how to run the check script, that the texts are shared by the iPhone and Mac records, that Bulgarian cannot be entered, and that promotional text can be edited without a new build.

ROLES:
- BASE WRITER: writes en-US and he completely, locales.json, both READMEs, the check script and its test; runs the script on en-US and he; does NOT write the other 18 folders.
- TRANSLATOR A / B (9 app locales each; the prompt names them): translate from en-US (he as a second reference for tone) into each of your locales; keep each file within the limits (shorten gracefully rather than truncate); run node scripts/appstore/check-listing.mjs after each locale; use the app's own vocabulary of shared/i18n/messages/<locale>/; never touch another translator's folders or the base files; if the base files are missing, STOP and report (do not write them yourself).
- VERIFIER (reads everything, edits nothing): runs the check script; reads every locale's name/subtitle/keywords/promotional text in full and the first 1500 characters of each description; refutes: wrong language or script, machine-translation errors, English leftovers (other than brand/product terms), forbidden platform mentions, claims the product does not make, limit violations the script missed, keyword lists that waste space, inconsistency with the app's vocabulary; also checks the test file really runs under node --test and the README field names match App Store Connect (per APPSTORE-FACTS.md). Findings with file, quote, severity, suggested text.
- FIXER: applies the verifier's findings (all severities when cheap), re-runs the check script and the scripts tests, lists what it changed per locale.

AMENDMENTS 2026-11-08 (from the verified research, docs/apple-tasks/APPSTORE-FACTS.md - binding for translators, verifier and fixer):
- keywords.txt limit is 100 BYTES of UTF-8, not 100 characters (Hebrew/Arabic/Cyrillic letters take 2 bytes, CJK/Thai/Devanagari 3): the check script counts Buffer.byteLength(text, 'utf8'); translators keep the strongest 3-6 terms and may mix in Latin terms (e.g. "diary") where natural.
- The Mac App Store record cannot carry the same app name as the iPhone record in a localization: add name-mac.txt = "Your Personal Diary for Mac" (Latin letters, 27 chars, identical in every folder) and say in both READMEs that it is the Mac record's name; subtitle, description, keywords and the rest are shared.
- Name: 2-30 characters. What's New is not available for version 1 (keep whats-new.txt for the first update; the README says so).
- The check script also rejects "©" nowhere (fine) and treats "App Store"/"Mac App Store"/"iPhone"/"Mac"/"Face ID"/"Touch ID" as allowed terms.

Until then: NEVER write 16 (or any number) as the minimum age in new texts - use {{MINIMUM_AGE}} in legal pages and read legal/settings.json elsewhere.
