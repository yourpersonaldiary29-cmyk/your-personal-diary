# Microsoft Store listing images - screenshots and logos

Real screenshots of **Your Personal Diary** (desktop, 1920 x 1080 PNG) for the Microsoft Store
listing in English (`en-US/`) and Hebrew (`he-IL/`), plus the optional Store logos (`logos/`).
Everything here is generated by one command (see "How to regenerate") from the app's own UI, with
two fictional accounts ("Dana Levi" / "דנה לוי") and the app's built-in sample data. No real
person, address or e-mail appears in any image.

How this set follows them: 10 desktop screenshots per language (the maximum), PNG, 1920 x 1080
(above the 1366 x 768 minimum, 16:9 like the maximized app window), 53-123 KB each, no added
logos, frames or marketing text - they are captures of the real pages of the app and no picture
is edited after it was taken. The capture-time adjustments are to the *data* and the *viewport*:
fictional accounts, toasts removed, and a page scrolled so that a tall card or calendar grid is
fully in the picture and the bottom edge does not run through a line of text where the page
allows it (see "Checks made on every image"). Each caption is under 200 characters.

**One capture shows a page layout that no user sees exactly like this** - disclosed here for that
reason (Policy 10.1 above): in `09-settings-language-and-privacy.png` the **Account card is
hidden** for the capture, by one injected CSS rule (`.settings-language + .card { display: none }`
in `scripts/store-shots/shoot.mjs`; the app itself is untouched). On the real Settings page the
Account card (first name, last name, user name, e-mail address, the list of connected devices)
sits between the Language card and the Display card. Everything that *is* in the picture is the
real, unmodified UI. Why it is hidden instead of shown without an address (both checked against the
running server on 2026-10-04):

- an account cannot exist without an e-mail address - `POST /api/auth/register` and
  `PUT /api/auth/profile` both answer `400 VALIDATION` (field `email`) for a missing or empty
  address, so the card always shows one (here it would be the fictional `dana@example.com`, and
  the task for this shot is "no account e-mail visible");
- even without an address the card would not fit: the page title and the Language, Display and
  Privacy cards already fill the 1080 px viewport, and the Account card adds several hundred pixels
  between them, so the language picker and the Privacy card - the two things this shot is about -
  could never be in one picture.

Owner's decision: this is not expected to be a certification risk either way. If a capture with no
page edit at all is preferred, delete the `addStyleTag` line in `settingsLanguageAndPrivacy`
(`shoot.mjs`) and re-run: shot 09 then shows the Language card and the Account card (with the
fictional address) but not the Privacy card, and its caption should drop the privacy half.

Store logos: 300 x 300 (icon only, transparent corners), 1080 x 1080 and 720 x 1080 with the icon
and the name "Your Personal Diary" in the top two-thirds and an empty bottom third; name colour
#1b2f4f on #f4f6f9 has a contrast ratio of about 13:1 (requirement 4.5:1).

Note on the "top two-thirds" guideline: it is a display recommendation for the Store's own text
overlays, not a certification requirement. The captures are full pages of the app, so the bottom
third naturally contains content; the key message of every shot (page title, main card, chart,
answer) is in the top two-thirds.

## How to regenerate

One command from the project root (Windows, Microsoft Edge installed):

```
node scripts/store-shots/run.mjs
```

It builds the UI into the scratch tool folder (`C:\Users\AVI\Projects\mpd-store-tools\dist`, override
with `MPD_STORE_TOOLS`), starts the diary server from source on port 47641 with a **temporary**
data directory in that folder, creates the two fictional accounts with the app's own sample data
(`POST /api/settings/seed-demo`, the endpoint of the Settings button "Load sample data", 240 days)
plus a few extra entries for today and yesterday and pleasant replacements for the generator's
planted low-mood days of the last month (so the home page, the trends and the "compared with the
previous period" sentence of a listing screenshot are encouraging), takes the 20 screenshots with
headless Edge (playwright-core, viewport 1920 x 1080, device scale factor 1, light colour scheme,
browser locale of the account), renders the three logos, then stops the server and deletes the
temporary data directory and the made-up passwords. Nothing is installed in the project and the
user's real data directory is never touched.

One-time prerequisite, in the tool folder only (never in the project):

```
cd C:\Users\AVI\Projects\mpd-store-tools
npm init -y
npm install playwright-core
```

Useful flags: `--skip-build` (reuse the last UI build), `--only 04,08` (only these shot numbers),
`--lang he-IL` (one listing language), `--skip-logos`, `--keep-data` (keep the temporary accounts
for another run). The pieces can also run on their own: `scripts/store-shots/seed.mjs` (accounts
and data; server must be running), `shoot.mjs` (screenshots), `logos.mjs` (logos); shared settings
are in `config.mjs`.

Dates in the pictures are the day of the run (the demo data is generated backwards from "today"),
so re-run shortly before uploading if a current date matters.

For every shot the run prints the file size and what the bottom edge of the picture does
("bottom edge clean", "clean after scrolling +100 px", or "cuts ..." with the text that is cut),
and a one-line summary at the end; see "Checks made on every image".

## Checks made on every image

Each PNG was opened and inspected after the run (not only generated):

- exact size 1920 x 1080, PNG, well under 50 MB;
- the right language, and for Hebrew a mirrored (RTL) layout: navigation on the right, sliders
  filling from the right, tables and chips right-aligned;
- no error toast, no spinner or "loading" text, no untranslated message key, no empty card;
- no personal data: the fictional first name "Dana" / "דנה" only; the account's e-mail address is
  not in any picture (the Account card is hidden in the Settings capture, see the disclosure in
  "How this set follows them");
- no horizontal scrollbar and nothing cut at the left or right edge; text sharp (device scale
  factor 1, system font Segoe UI). The only shortened texts are the long holiday names of the two
  calendar shots, which the app itself ends with an ellipsis (listed in the table above);
- the bottom edge (the last 64 px of every picture were inspected at 100 %). The pages are longer
  than the 1080 px viewport, so every picture ends somewhere inside the page. `shoot.mjs`
  (`snapBottomEdge`) moves that edge to the nearest position where it falls *between* lines of
  text, buttons, input boxes and table rows instead of through them - but only to a normal state of
  the app: the page at the very top, or the navigation row completely under the top bar, with the
  page title still in view. Result of the last run: **clean in 14 of the 20 pictures**
  (02, 03, 04, 05, 06, 08, 09 in both languages). In the other six the edge still cuts something,
  and they are left that way on purpose:
  - `01-home.png` and `10-dark-theme.png` (both languages): the heading of the second habit
    ("Drinking water" / "שתיית מים") is cut in half. These two stay at the top of the page - the
    home page as it looks right after signing in, with the navigation - and no other allowed
    position is clean either;
  - `07-statistics.png` (both languages): the top 12 px of the "Show as table" / "הצג כטבלה"
    button show at the very bottom. A clean position would need the page title to go under the
    top bar.

  All six come from the same cause: at 1920 px the navigation row wraps to two lines (see the app
  notes below), which leaves a range of less than 20 px of allowed scroll positions (93-111 px).
  By the measured geometry, with a one-line navigation row (about 46 px lower) both pages would
  end cleanly at the top of the page. The script re-evaluates every edge on each run and prints
  the result per shot ("bottom edge clean" / "bottom edge cuts ..."), so nothing has to be
  changed here when the app changes;
- per shot: the home page has an entry today, a writing streak and 7-day averages; the new-entry
  form shows the example text and mood 9 with three emotions ticked (the sliders fill from the
  right in Hebrew); the diary is in Month view of the previous month; the English calendar shows
  the Easter-week holidays (Western and Orthodox, three of the eight labels ending in "...") and
  the Hebrew one the Tishrei holidays (one label ending in "...") with the whole six-row grid and
  the legend in view; the habits show progress bars; the first insight has its "why" disclosure
  open with the whole data table and only positive numbers; the mood chart with both lines and a
  "+" comparison with the previous period is visible; the search shows the question, the
  interpretation and the answer; the Settings shot shows the language picker and the Privacy card;
  the dark-theme shot has the dark theme applied everywhere (header, nav, cards).

Notes about the app itself that are visible in the pictures (reported to the main session; app
code is outside the ownership of this task, so nothing was changed there). After any of them is
fixed, `node scripts/store-shots/run.mjs` regenerates the whole set:

1. **Navigation row wraps at 1920 px** (the most visible one; in every picture that shows the
   navigation: 01, 05, 07, 10 in both languages and en-US 04). Nine items are on the first line
   and "Settings" / "הגדרות" is alone on a second one, because the sentence "Hello Dana, and
   welcome to your personal diary" (`.nav__greeting`, `src/components/layout/NavBar.tsx`) sits
   beside the list inside the 1152 px content column. The greeting also appears in the top bar
   and in the first card of the home page. It is also what keeps six bottom edges from being
   clean (see above).
2. **Long holiday names are cut with an ellipsis** in the calendar's day cells (04, both
   languages), e.g. "Good Friday (Weste...". Letting the label wrap to a second line, or a shorter
   rite qualifier at this width, would show the whole name (`src/pages/entries/entries.css`:
   `.holiday-badge--compact .holiday-badge__name` has `white-space: nowrap` and
   `text-overflow: ellipsis`).
3. **Read-only emotion chips have uneven padding** (03, both languages: "Calm", "Focused" /
   "רגוע", "מרוכז"): `.chip` in `src/styles/forms.css` uses `padding-inline: 0.75rem 0.2rem`,
   which is made for chips with a remove button; without the button the text sits 3 px from the
   end of the pill.
4. **Negative numbers inside Hebrew text** - worked around in the data, so no picture shows it: a
   negative number such as "(-0.7)" in the Statistics summary or "-0.03 points" in an insight's
   evidence table is rendered with the minus sign on the wrong side ("(0.7-)"). The capture
   therefore prefers an insight without negative numbers, and the seed data makes the month
   compare positively with the one before it.
